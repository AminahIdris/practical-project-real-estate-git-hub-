# Contributing

## Workflow

1.  Create or select a task in `TASK.md`.
2.  Read the relevant documentation.
3.  Create a focused branch.
4.  Make the smallest reasonable change.
5.  Run relevant tests.
6.  Update documentation if behavior or contracts changed.
7.  Update `IMPLEMENTATION.md`.
8.  Open a pull request.

## Commit Style

Prefer small, descriptive commits:

``` text
feat: add lead creation endpoint
fix: reject invalid bedroom count
test: add lead qualification boundary cases
docs: update deployment runbook
```

## Pull Requests

A PR should state:

-   What changed
-   Why it changed
-   Files/components affected
-   Tests run
-   Any known limitations
-   Any documentation updated

Do not mix unrelated refactoring with feature work.
